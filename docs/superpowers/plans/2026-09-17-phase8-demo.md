# Phase 8: Streamlit Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Streamlit app that talks to the Phase 7 API. It has five pages (price and forecast, search, listing check, area explorer, about) and needs two new read-only area endpoints on the API.

**Architecture:**
- **API side:** `api/areas.py`, a new API component, precomputes monthly area medians at startup. `api/routes/areas.py` serves them.
- **Demo side:** `demo/client.py` is an httpx client that holds the API key server-side. `demo/app.py` and `demo/pages/*` are a Streamlit multipage app, tested with `streamlit.testing.v1.AppTest` against a fake client.

**Tech stack:** Streamlit, httpx, FastAPI (Phase 7), polars, psycopg2.

**Spec:** `docs/superpowers/specs/2026-09-17-phase8-demo-design.md`

## Global constraints

### Architecture and safety
- **API access:** the demo talks only to the API over HTTP. It never imports `psycopg2`, `mlflow`, `models.*`, `search.*` or `listings.*`, and a test scans `demo/` for those imports.
- **Keys:**
  - The demo reads `DEMO_API_URL` (default `http://127.0.0.1:8000`) and `DEMO_API_KEY`.
  - The key is sent only as `X-API-Key` from the server-side client. It is never displayed or logged.
- **Environment:** `load_dotenv()` runs before settings are read. The project database is on port 5433; never connect to 5432.

### Page content
Every page:
- shows "Data as of 2023-03-17";
- never shows a number without its range;
- shows the API's `reason` for horizons that are not deployed;
- shows a "synthetic listings" note on listing pages.

### Area statistics
- **Rows:** clean home sales from 2015 on, per `models.price.data.HOMES_SQL` filters with `is_clean` true.
- **`market_kind`:** as in Phase 6 (`villa_plot` for plot-basis villas).
- **Summary:**
  - the last 12 months before the data end, against the 12 before that;
  - areas with fewer than 20 sales in the last 12 months are omitted.
- **History:**
  - the last 96 months;
  - months with fewer than 5 sales get a null median.

### Testing and git
- **Tests:** no network and no GPU.
  - Demo page tests use AppTest with a fake client injected through `demo.client.get_client` (monkeypatched).
  - Test files live at `tests/demo/test_demo_<topic>.py` and `tests/api/test_api_areas.py`, with no `__init__.py`.
- **Git:**
  - Stage explicit files only, and commit with a pathspec: `git commit -m ... -- <files>`.
  - The trailer is `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
  - Never commit `.env`, `data/`, `mlruns/`, `.superpowers/` or `graphify-out/`.
- **Parallel work:** tasks marked parallel-safe run only their own tests, and format only their own files.

## Task 1: Streamlit dependency and the API client

**Files:**
- Modify: `pyproject.toml` and `uv.lock` via `uv add streamlit`; `demo/__init__.py`
- Create: `demo/client.py`, `tests/demo/test_demo_client.py`

**Interfaces.** `demo.client` produces:
- `ApiProblem(Exception)`, with attributes `status: int`, `code: str`, `message: str`, `field: str | None` and `request_id: str | None`.
- `ApiClient(base_url: str, key: str | None, transport: httpx.BaseTransport | None = None, timeout: float = 30.0)`, with these methods. Each returns parsed JSON (a dict).

  | Method | Request |
  |---|---|
  | `ready()` | `GET /v1/ready` |
  | `price(body)` | `POST /v1/price` |
  | `forecast(body)` | `POST /v1/forecast` |
  | `search(q, k=10)` | `GET /v1/search` |
  | `listing_flags(listing_id)` | `GET /v1/listings/{id}/flags` |
  | `check_listing(body)` | `POST /v1/listings/check` |
  | `areas()` | `GET /v1/areas` |
  | `area_history(area_id)` | `GET /v1/areas/{id}/history` |

- `client_from_env(environ=None) -> ApiClient`, which reads `DEMO_API_URL` and `DEMO_API_KEY`.
- `get_client() -> ApiClient`. It is a module-level cached factory that the pages use (`functools.lru_cache`), and tests monkeypatch it.

**Error mapping.**

| Situation | `ApiProblem` |
|---|---|
| Non-2xx response with the JSON envelope | `status`; `code`, `message` and `field` from `error`; `request_id` from the body or the `X-Request-ID` header |
| Non-JSON error | `code="http_error"`, `message=f"HTTP {status}"` |
| `httpx.ConnectError` or `httpx.TimeoutException` | `status=0`, `code="unreachable"`, `message=f"cannot reach the API at {base_url}"` |
| No key | `ApiClient` is still built, but every call raises `ApiProblem(0, "no_key", "DEMO_API_KEY is not set")` before sending anything |

- [ ] **Step 1: Run `uv add streamlit`, then check `uv run python -c "import streamlit, streamlit.testing.v1"`.**

- [ ] **Step 2: Write the failing tests.** Each test uses `httpx.MockTransport`. They must check:
  - every method's HTTP method, path, query and JSON body;
  - that the `X-API-Key` header is sent;
  - the envelope → `ApiProblem` mapping, including `field` and `request_id`;
  - that a non-JSON 502 gives `http_error`;
  - that a `ConnectError` gives `unreachable`, with the base URL in the message;
  - that no key gives `no_key` without sending a request (the transport records its calls);
  - `client_from_env` defaults;
  - that the base URL's trailing slash is handled;
  - a source scan: no file under `demo/` imports `psycopg2`, `mlflow`, `models`, `search` or `listings`. Walk `demo/**/*.py` with `ast`.

- [ ] **Step 3: Implement `demo/client.py`.** Set the `demo/__init__.py` docstring to `"""Streamlit demo UI (Phase 8)."""`, with no heavy imports.

- [ ] **Step 4:** Run `uv run pytest -q -W error tests/demo`, then ruff on your own files only. Commit with a pathspec and the message `feat(demo): API client for the Streamlit demo`.

## Task 2: Area statistics on the API

**Files:**
- Create: `api/areas.py`, `api/routes/areas.py`, `tests/api/test_api_areas.py`
- Modify:
  - `api/settings.py`: `COMPONENTS` gains `"areas"`
  - `api/state.py`: adds `areas` to `default_loaders()`
  - `api/app.py`: includes the router
  - `tests/api/api_fixtures.py`: `FakeAreas`, plus a fake loader

**Interfaces.** `api.areas` produces:
- `AREA_SQL`: selects `area_id`, `instance_date`, `property_type`, `property_sub_type`, `rooms`, `area_sqm`, `price_aed` and `is_clean`, the same scope as `HOMES_SQL`.
  - **Simplest correct approach:** call `models.price.data.load_homes(settings, TrainConfig())`, which returns rows with `derive_segments` columns, `areas` and `data_end`, then compute `market_kind` with the same expression Phase 6 uses. Reuse `models.forecast.rows`'s helper if it exposes one; otherwise put a tiny shared function in `models/forecast/rows.py` and import it.
- `AreaStats(summary: pl.DataFrame, history: pl.DataFrame, names: dict[int, str], data_end: date)`, with:
  - `.from_homes(rows, areas, data_end)` (pure, and tested on synthetic rows);
  - `.load(settings)`;
  - `.summary_records() -> list[dict]`: each record has `area_id`, `name`, `median_ppsm_12m`, `change_12m` and `sales_12m`, sorted by `sales_12m` descending;
  - `.history_records(area_id) -> dict | None`: `{area_id, name, data_end, series: [{market_kind, points: [{month, median_ppsm, sales}]}]}`.

**Routes** (key required):
- `GET /v1/areas` returns `{"data_end": ..., "areas": [...]}`.
- `GET /v1/areas/{area_id}/history` returns the history, or 404 with `f"area {area_id} not found"`.

**Component:**
- Name: `areas`.
- Version: `f"data_end:{data_end}"`.
- Loader: `AreaStats.load(DbSettings.from_env())`.

**Tests:**

`from_homes` on a hand-made frame:
- 12-month medians;
- the change ratio;
- omission below 20 sales;
- a null median for months with fewer than 5 sales;
- `villa_plot` separation;
- the 96-month cap.

Routes with a `FakeAreas`:
- `GET /v1/areas` returns 200;
- an unknown area in the history route returns 404;
- a missing component returns 503.

Settings:
- the default components now include `areas`.

Database:
- a DB test loads the Phase 2 fixture (`tests/fixtures/price_sample.csv` through `ingestion.pipeline.run_pipeline`) into `pg_test_db` and checks that `AreaStats.load` returns a non-empty summary or history.

**Steps:**
1. Write the failing tests.

4. Run ruff.

## Task 3: The Streamlit pages

**Files:**
- Create: `demo/app.py`, `demo/ui.py` (shared rendering helpers), `demo/pages/1_Price_and_forecast.py`, `demo/pages/2_Search.py`, `demo/pages/3_Listing_check.py`, `demo/pages/4_Area_explorer.py`, `demo/pages/5_About.py`, `tests/demo/demo_fixtures.py`, `tests/demo/test_demo_pages.py`

**Interfaces.**

`demo.ui` produces:
- `DATA_NOTE = "Data as of 2023-03-17 (Dubai Land Department)."`
- `SYNTHETIC_NOTE = "Listings are synthetic, generated over real DLD sales, and labelled."`
- `show_problem(problem: ApiProblem)`: renders `st.error` with the message, plus the request id in `st.caption`. For `no_key` and `unreachable` it adds a setup hint that names `DEMO_API_URL` and `DEMO_API_KEY`.
- `money(aed: float) -> str`: `"AED 1,455,490"`.
- `pct(x: float) -> str`.
- `forecast_rows(forecast: dict) -> list[dict]`: one row per horizon, with columns horizon, point, low, high, confidence, note. The note is the LOW message or the not-deployed reason.
- `cached_areas()`: `st.cache_data(ttl=600)` around `get_client().areas()`.

**`demo/app.py`:**
- `st.set_page_config(page_title="Zestimator", layout="wide")`;
- a title and an intro;
- a sidebar showing API status from `ready()`, per component, as up/down with the version;
- `DATA_NOTE`;
- links to the pages.

**Pages.** Follow the spec's Architecture table. Every page uses `get_client()` and wraps calls in `try/except ApiProblem → show_problem`.

| Page | Behaviour |
|---|---|
| Price & forecast | A `st.form`. Area choices come from `cached_areas()`, by name, and fall back to a text input if the areas call fails. On submit it calls `price()` and `forecast()` with the same body, then shows: a metric card with the estimate and the 80% range, the `forecast_rows` table, and the drivers list or `"No single factor moved this forecast by 0.5% or more."`, plus the exclusions list. |
| Search | A text input with 3 example buttons, and k as a slider from 5 to 20. It shows the "understood" fields, the notes, and each hit with its title, price, area, reasons, and duplicate/fraud badges if they are present in the hit dict, plus `SYNTHETIC_NOTE`. |
| Listing check | Two tabs. **Existing listing** takes an id and calls `listing_flags`. **New listing** is a form that calls `check_listing`, with an optional "prefill from listing id" that fills the form from `listing_flags`. The flags endpoint doesn't return listing text, so prefill only fills the id-related notes; keep it simple and note that. Both show a duplicates table and flag cards, plus `SYNTHETIC_NOTE`. |
| Area explorer | A `st.dataframe` of `summary_records`, sortable. A select box picks an area, and a second one picks a `market_kind`. It shows `st.line_chart` of `median_ppsm` by month and `st.bar_chart` of sales. |
| About | Static markdown: the data source and limits, how each model is gated, the current deployment status (live from `ready()`), and links to the README and the architecture page URL `https://claude.ai/artifact/6keTdjksn2nWLnkVmNbMRw`. |

**`tests/demo/demo_fixtures.py`:** a `FakeClient` that returns realistic dicts:
- the forecast has 3m deployed, and 1y/3y `not_deployed` with reasons;
- `areas` has 3 areas;
- search returns 2 hits.

It takes a `fail` mapping from method name to `ApiProblem`, so tests can make any call fail.

**Tests** (`AppTest.from_file("demo/pages/...")`):
1. Every page, plus `app.py`, runs without exception.
2. On the price page, submitting the form shows an estimate containing "AED".
3. The price page shows the 1y reason text.
4. On the search page, typing a query shows 2 results.
5. Listing check, existing tab: an id with flags shows the flag names.
6. Area explorer: the table has 3 rows, and selecting an area renders a chart.
7. With `forecast` failing as `ApiProblem(503, "unavailable", "forecast is unavailable: ...", None, "rid1")`, the page shows the message and "rid1".
8. With `no_key`, the page shows the setup hint.

Patch `demo.client.get_client` to return `FakeClient`. `AppTest` runs the script in-process, so a monkeypatch on the module works; if it doesn't, set an env var that `get_client` reads to select a fake by import path.
